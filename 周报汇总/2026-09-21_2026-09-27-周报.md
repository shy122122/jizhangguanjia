## 一、本周概要

本周的主线是**把「明账」从静态原型推进到可运行的系统**。三条线并行：C 端前端完成目录整理并从写死的 mock 数据切换到真实接口调用；后台管理系统从 PRD 立项推进到后端骨架成型；数据库脚本作为独立资产完成归档。

## 二、需求与设计（PRD / UI 原型）

- **后台管理系统 PRD v1.0 立项** — 补入本次开发的关键约束：**现有数据库表结构冻结**，后台不得修改 C 端的 12 张表 / 6 个视图 / 8 个 CHECK 约束；后台只允许新增自己的表，且不得与业务表建立外键（否则 C 端的级联删除会被拖住）。同时明确运营端与 C 端的鉴权隔离、强制审计、数据脱敏三条安全底线。

## 三、前端开发

- **C 端目录结构重整** — 原 `整理版/` 下的 `preview` / `pages` / `assets` / `docs` 共 82 个文件移出，改由 `fronted/整理版/`（89 个文件）承载。整理后前端工作目录与交付目录分离，页面原型不再混在交付代码里。
- **前端接入真实后端** — 从纯静态 mock 切换为真实调用：新增统一请求封装（自动携带 token、401 自动登出、错误统一提示）与数据驱动渲染层，替代原先写死在 HTML 里的数组和数字。涉及 `fronted/整理版/assets`、`backend/src`、`backend/scripts` 等 211 个文件。
- **后端脚本补齐** — C 端后端新增 7 个脚本，配套接口调试与数据准备。

## 四、后台管理系统（运营端）

- **项目结构落定** — `backend` + `frontend` 分离，作为独立可交付单元，与 C 端代码互不引用。
- **后端骨架成型**（21 个源文件）— 配置层、数据库连接层、独立鉴权、统一错误映射、工具层五块就位：
  - **数据库连接层带 DDL 拦截** — 运行时拒绝执行 `ALTER` / `DROP` / `CREATE` 等语句，作为「结构冻结」约束的第二道防线（第一道是数据库账号权限）。后台即使代码写错也改不动表结构。
  - **独立鉴权** — 运营账号走独立用户表与独立 JWT scope，与 C 端用户体系完全隔离；token 每次请求回库校验，支持强制下线。
  - **工具层** — 金额按「分」做整数运算（避免 DECIMAL 浮点误差）、周期计算、手机号/邮箱/IP 脱敏、入参校验。
- **后台前端地基**（4 个文件）— 设计令牌与静态资源就位，沿用 C 端的品牌色与中性色体系。

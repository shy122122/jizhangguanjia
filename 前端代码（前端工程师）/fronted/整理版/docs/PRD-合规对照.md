**为什么同一个首页要做 5 屏？**
PRD 4.4.4 把「预算穿透」定义为产品的核心差异化，而穿透的表现形态随预算健康度变化：
平稳 → 配额 → 告急 → 濒临穿透 → 赤字。五种状态是一次设计走查的单位，不是五个不同页面。
在原型里用页面表达，是为了让评审能逐屏对比；正式开发时它们是同一组件的不同 props。

## 五、已知偏差（需 PM 决议）

### 偏差 1 · 分类预算「关注区间」的阈值

- **原型**：分类预算 > 70% 即标为「进入关注区间」，用 amber 呈现。
- **PRD 13.5.2**：只定义 80% 一个分界（> 80% → amber）。
- **PRD 4.4.3 示意图**：餐饮 77% 无 ⚠️ 标记。
- **建议**：若采纳原型的 70% 预警带，需回写 PRD 13.5.2；否则把 04 页餐饮 77.2% 与文案「进入关注区间」一并降级为常态绿。
- **当前处理**：**保留原型设计**，仅修正红色误用（见修正 1）。原因是它不与任何硬性规则冲突，且提前 10 个百分点预警符合 PRD 4.4.4「预警要柔性」的取向。

### 偏差 2 · 第三方品牌色

- 微信 `#07C160`、支付宝 `#1677FF` 出现在 15 / 18 / 21 三页。
- 二者**不在 PRD 13 章色板内**，但属于平台标识，不应改色。
- **建议**：在 PRD 13 章补一条「第三方支付渠道标识沿用其官方品牌色，不受本规范约束」。

### 偏差 3 · 状态切换器是原型期装置

`shell.js` 的 `switcher()` 渲染右下角浮层，用于评审时逐屏走查。
**正式开发时删除该函数与页面里 `[data-shell="switcher"]` 注入点即可**，其余代码不受影响。

### 偏差 4 · 两张 PRD 站内页未单独出图

流水「详情 / 编辑」与「账户管理」在 PRD 5.1 中有节点，但原型中由列表行内操作与设置页入口承载。
- **建议**：若评审需要，可基于 13 与 21 快速补两屏；也可接受当前处理并在 PRD 5.1 标注「并入上级页面」。

## 六、原型期新增（PRD 未涉及）

以下文件不属于产品功能，是交付这套原型的工程基建：

| 文件 | 作用 |
| --- | --- |
| `index.html` | 原型导航台，按模块陈列 23 屏，支持搜索 |
| `assets/js/routes.js` | 路由表，导航与卡片的唯一数据来源 |
| `assets/js/shell.js` | 共用外壳（侧边栏 / 顶栏 / 底部 Tab / 切换器）注入 |
| `assets/css/tokens.css` | 设计令牌（PRD 13 章的 CSS 变量形态） |
| `assets/js/tailwind.config.js` | Tailwind 主题配置（PRD 13 章的类名形态） |

设计令牌有两份形态是刻意的：Tailwind 配置供页面类名使用，CSS 变量供 JS 动态计算与深色模式覆盖使用。**两者的取值必须保持一致，修改时需同步。**

# 明账 · 后台管理系统

面向运营专员的独立管理后台，依据《明账-后台管理系统-PRD-v1.0》实现。

## 技术栈

- 后端：Node.js、Express 5、MySQL 8、原生 SQL
- 前端：原生 HTML/CSS/JavaScript 单页应用，不依赖外部 CDN
- 鉴权：独立后台账号、独立 JWT 密钥、`scope=admin`、8 小时会话
- 数据：复用明账 C 端数据库，但后台运行账号使用收窄权限

## 目录

```text
后台管理系统（运营专员）
├─ backend
│  ├─ sql/01_admin_schema.sql     仅创建后台自己的 5 张表
│  ├─ scripts/                    迁移、初始化与自检
│  └─ src/                        路由、服务、鉴权、数据库
└─ frontend
   ├─ index.html                  单页入口
   └─ assets/                     样式、接口封装与页面逻辑
```

## 首次运行

```powershell
cd "D:\workspace\my projects\后台管理系统（运营专员）\backend"
npm install --registry=https://registry.npmmirror.com
npm run migrate
npm run seed
npm start
```

访问 `http://localhost:3001`。初始化账号由 `backend/.env` 的
`ADMIN_SEED_USERNAME` / `ADMIN_SEED_PASSWORD` 决定；生产部署前必须更换。

## 已实现模块

- 独立后台登录、失败锁定、滑动续期、即时强制下线
- 数据看板：用户、账本、流水、预算设置率、导入成功率、DAU/留存可用性
- 用户列表：搜索、状态/预算/异常筛选、排序、分页、服务端脱敏
- 用户详情：账号资料、数据概览、安全状态、处置历史
- 六类处置：解锁、强制下线、停用、恢复、标记注销、开发环境临时密码重置
- 五个只读数据页：账户、分类、预算、流水、导入批次
- 单用户 JSON / CSV 导出，原因必填并留痕
- 全局关键词规则：增删改、停启用、优先级命中预览
- 分类模板与账户模板维护，模板变更不追溯已有用户
- 审计日志：筛选、详情前后对比、CSV 导出且导出本身留痕

## 与 C 端的最小集成

为让“模板只影响新用户”和 DAU/留存真正产生数据，本次同步调整了现有 C 端两处代码：

- `backend/src/services/auth.service.js`：注册时优先读取后台分类/账户模板，表不可用时回退代码常量。
- `backend/src/middleware/auth.js`：鉴权成功后按用户、日期写入日活去重表；不可用时降级，不影响记账。

迁移脚本只给 C 端 `mz_app` 增加模板只读与日活表写入权限，不授予后台账号、审计日志或
其他后台配置的访问权限。C 端需要在方便时重启一次才能加载这两处集成代码。

## 安全边界

- 不复用 C 端 token 或鉴权中间件。
- 不提供模拟登录、批量处置、物理删除用户。
- 不提供任何修改用户流水、预算、账户、分类的接口。
- 运行时数据库层主动拒绝 DDL。
- 新表不对 C 端表建立外键，用户注销后审计记录仍保留。
- 联系方式由后端脱敏，前端永远拿不到用户明文手机号/邮箱。
- 查看流水、导出用户数据、所有写操作均记录审计。

## API 前缀

所有后台接口使用 `/api/admin`，健康检查使用 `/api/health`。成功响应统一为
`{ "ok": true, "data": ... }`，失败响应统一为
`{ "ok": false, "error": { "code": "...", "message": "..." } }`。
